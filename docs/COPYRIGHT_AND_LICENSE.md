# Copyright and License Policy

[Back to README](../README.md)

This repository is public. Public visibility is not the same as permission to reuse, redistribute, or create derivative works.

## License decision point

Do not add a license automatically.

Rahul must explicitly choose one of:

1. Leave the repository without a license.
2. Apply one license to the entire repository.
3. License software code and educational notes separately.

Before adding a license, Codex must explain:

- permissions granted;
- attribution requirements;
- modification and redistribution rules;
- commercial-use implications;
- patent terms when relevant;
- warranty and liability disclaimers;
- suitability for code, prose, diagrams, exercises, or all of them;
- the effect of third-party material;
- contributor implications.

Do not select or add the actual license without explicit approval.

## No-license state

Until a license is chosen:

- do not add `LICENSE` or `LICENSE.md`;
- do not describe the repository as open source;
- do not assume that public visibility grants general reuse rights;
- keep license references in README and documentation accurate.

## Separate-license option

If code and notes are licensed separately:

- identify the exact paths covered by each license;
- use clear root notices;
- add per-directory notices only when needed;
- clarify the status of code embedded inside educational notes;
- avoid contradictory terms;
- audit contributor and third-party implications.

## Original-writing rule

Write explanations, diagrams, examples, exercises, and projects in original language.

Codex must:

- paraphrase sources;
- cite the source of important technical claims;
- use only short quotations when exact wording is necessary;
- mark quotations clearly;
- preserve required attribution for legitimately reused material;
- avoid recreating a book, course, article, documentation chapter, paid problem set, or proprietary training resource.

A citation does not make extensive copying acceptable.

## External code and examples

Before reusing external code:

1. Identify its license.
2. Confirm that the intended use is permitted.
3. Preserve required notices.
4. Prefer a small original example.
5. Avoid code whose license is absent, unclear, or incompatible.

Do not copy examples from employer systems, private repositories, paid courses, interview take-homes, or confidential documents.

## Privacy and confidentiality

Do not commit:

- credentials, secrets, tokens, or private keys;
- personal identifiers beyond what Rahul deliberately publishes;
- relationship, medical, or financial information;
- employer-confidential code, data, logs, architecture, or screenshots;
- customer, supplier, employee, or candidate data;
- proprietary datasets;
- copied production incidents;
- unrelated conversation transcripts.

Use synthetic names, records, logs, paths, service boundaries, and credentials.

## License-change procedure

A license change is complete only when:

1. Rahul approves the licensing option and exact text.
2. Covered paths are explicit.
3. Existing third-party material is audited.
4. README and related guidance are consistent.
5. Required notices are present.
6. The change is reviewed before commit or publication.
